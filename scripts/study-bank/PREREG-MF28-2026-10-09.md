## What is new (A90's lessons, each with its mechanism)

1. **Plug-back (A90's largest drop class, 8 of 18; seven S keys reached on the FIRST
   ascending substitution).** Every item declares `plugback {substitutable, verify, why}`.
   `mf28-checks.mjs` PLUG: the natural order is ascending, or descending on a greatest /
   maximum / largest / most stem; **P2** a substitutable item's `verify(v)` must be true for the
   key and false for all three distractors (so the declared check is real) and the key must sit
   at try >= 3 - a key at try 1-2 on a substitutable ask is a return; **P3** a key at try 1-2 on
   an ask declared not substitutable prints a `(read) PLUG` line (parameter asks marked), and I
   read every one by hand at stage 0: a substitutable one is a return. The brief bans, on S and
   lower-interior keys, the solution x, a zero, the input where f(x) = c, "the value of k" making
   a printed condition true, and a short forward computation; it asks for a derived quantity one
   step past. **Tested during authoring**: authors run `mf28-part-check.sh` on every item as it
   is written (sandbox verify + slot + mf28-checks on the single item). Calibration: on algf27's
   frozen 50 the key sits at try 1-2 on 25 items (6 parameter asks); on adv25's 59, 21 (2).
2. **The option-pair rule extended to derived multipliers (A90 B01, D04).** `mf28-checks.mjs`
   DPAIR (gating): key / option, either way, equal to a number one step from the printed
   numbers - printed integer n - 1 or n + 1, or the sum of two different printed integers (all
   >= 2; a printed 1 and decimals were pure noise on calibration). Difference / sum equal to such
   a number is a `(read)` line. Selftest 11/11: B01 (3 = 4 - 1) and D04 (4 = 3 + 1) gated by
   DPAIR and NOT by PAIR, a clean item, a sum-of-two-printed case, seven PLUG cases including
   D05's S-key parameter shape. **Calibration, recorded before use:** DPAIR gates on 11 of
   algf27's frozen 50 (B01 D04 plus B09 B10 B13 that the gate dropped for other reasons, and 6
   kept items) and 10 of adv25's frozen 59 (9 kept). So it also refuses items the graders
   passed: it is an authoring constraint designed around with the checker, not a claim that
   every hit is a tell. PAIR / RUN / DIR (algf27-checks.mjs) are imported unchanged.
3. **Authors write one small file per item, 5-7 items per run**, to `mf28-parts/`, folded by
   `mf28-assemble.mjs`. Runs: A 5+5, B 5+4, C 5+5, D 7, P 6, Q 6, R 6, S 6 (11 runs).
4. **Graders work in private folders and never modify their stage-1 file, enforced.**
   `mf28-grade-stage.mjs`: each grader-third gets `mf28-grade/<g>-<h>/` holding ONLY the cold
   render; run 1 writes `stage1.json` and ends; `snap` checks it (every id, render sha), copies
   it to `mf28.ws-<g>-<h>.stage1.json`, makes both read-only, records the sha and time in
   `mf28.coldshas.json`, and only THEN places the keyed files in the folder; run 2 (the same
   grader, continued) writes `stage2.json`. `mf28-coldcheck.mjs`: the grader's own stage1 still
   hashes to the snapshot, every stage-2 row carries every snapshot field unchanged, and the
   snapshot predates the release. A grader-third that fails the coldcheck is discarded and
   re-run fresh (as A90 did), recorded.
5. **Re-dump the live bank immediately before freeze** (`mf28-dump.mjs`), and read every live
   maths row added since the authoring dump against all items; `math-mechanism-dup` re-runs
   over the live table and its NEAR list is read, not only FLAGs (A90 found D02 there).

## Authoring rules (MF28-AUTHOR-BRIEF.md carries each verbatim)

algf27's rules 1-14 and adv25's rules 1-11, merged: one mechanism per item, distinct from the
batch, every live maths row and every prior / held SAT Algebra and Advanced Math item (2-4
keyword searches per item with `mf28-kw.mjs`, recorded in `dup_search`); `solve` +
`distractor_solve` for every distractor; distractors from different named wrong paths with
the hub / composite / +-pair / closure / run / grid / decimal-shift / singleton-class bans;
per-distractor `distractor_meta` with direction and `stem_predicts_direction: false`, >= 2
kinds, one strong, <= 1 omission/partial; `counter_error` on every S/L key; one-way asks
banned on S/L; `cheap_bound_check`; `shape_check` (every option legal and surviving every
qualitative property the stem hands over, >= 2 together); interior parity and complement
bans; error-kind direction balance within an author's items; medium = two real steps, hard =
a decision point Desmos does not bypass. **Plus rule 7 (PAIR + DPAIR) and rule 8 (PLUG) as
above.** Author-only fields stripped by `mf28-strip.mjs`'s allow-list before any grader or
solver: `mechanism`, `quantity_asked`, `ask_type`, `plugback`, `shape_check`,
`distractor_meta`, `counter_error`, `cheap_bound_check`, `interior_parity_check`,
`arith_class_check`, `bounds`, `dup_search`, `self_audit`.

## Stage 0 — pre-flight, per author file, BEFORE the one return

`mf28-assemble.mjs <x>` folds the parts; `mf28-preflight.sh <file>` gates: `math-bank-helper
verify` (N/N keys, 3N/3N distractors; mutation of one key and one distractor body refused, on
the first file in), `mf28-slots.mjs`, **`mf28-checks.mjs` (PAIR, RUN, DIR, DPAIR, PLUG)**,
`check-sign-pair`, `check-key-is-composition`, `check-explanation-hygiene`,
`check-interior-niceness` (any parity / KEY-CLEANER / complement / denominators line is a
return), `stem-duplicates`, `check-math-near-dup`, `check-duplicate-option-sets`, merge-halves
CLOSURE on the single file. Reported and read: both hub checks, `key-rank-position`,
`check-key-magnitude`, `check-key-arith-class`, `math-mechanism-dup` (FLAG and NEAR).

By hand, on EVERY author's file: (a) for every extreme-key item, could a student read the
direction of the natural errors from the stem and strike all three without solving? (b) for
every `(read) PLUG` item, could a student check an option against the stem in one routine
step? (c) every `(read)` PAIR / DPAIR line. A yes is a return. Plus my hand keyword search per
item (`mf28-kw.mjs`), all recorded in `mf28.stage0.json` / `mf28.dupsearch.json`.

**One return per author**, carrying every stage-0 finding at once; the returned items re-run
all of stage 0. An item still failing after its return is **dropped before freeze**.
Batch-level, per domain, on the merged set: `key-extremity-gate` PASS and key-position band
(commissioned ± 3, scaled to drops): **Algebra S 8-14 / I 11-17 / L 8-14; Advanced Math S 4-10
/ I 7-13 / L 4-10.** A batch-level failure in a domain after the returns **stops that
domain** (the other proceeds).

**Re-dump before freeze** (point 5 above). A duplicate found there drops the item.

## Stage 1 — options-only attack (blind half), PER DOMAIN

`make-mf28-oo.mjs --domain alg|adv` (= make-algf27-oo.mjs per domain; EXCLUDE = the session
Algebra and Advanced Math cohorts + this cohort + v2; seed 20261042 / 20261043): one live
control per candidate from the same domain in the candidate's authored band, numeric only,
keys dealt flat, interleaved. Eligible today: Algebra hard 30 / medium 139; Advanced Math hard
48 / medium 118. Three samples of one Claude solver per render. `score-oo.mjs`.

Per domain: **HOLD that domain** if candidate minus control > **+10** points, or the
candidate unanimous-correct rate exceeds the control's by > **15** points. Ceiling: both bars
fire only while the control <= 90%; above that the domain's blind half is NOT MEASURED and that
domain stops. Unanimity alone never drops an item. An options-only result is never reported as
"does not leak".

## Stage 2 — with-source graders (decides per item)

Three fresh Claude graders (D, E, F), each over all frozen items in three runs (thirds of the
seeded order, positions 1-20 / 21-40 / 41-60; `mf28-strip.mjs` + `make-grade-render.mjs`), under
the folder protocol of point 4. Fields as algf27 plus `domain_judged`, with `option_pair_tell`
covering DPAIR and `plugback_tries` counting a forward computation as substitution
(MF28-GRADER-BRIEF.md). At most 2 graders at a time.

Drop rules (`mf28-verdict.mjs`, written before any grader runs; = algf27-verdict.mjs): **1** key
disputed by any; **2** not exclusive by majority; **3** distractors weak by majority; **4**
median >= 2 free strikes; **6** plug-back <= 2 routine tries by majority; **11** template of an
EARLIER item (seeded order) by >= 2; **EXT-1** any `drop_recommend`. Confirmed by me from any
one grader: key free-strikable (4), incoherent path (5), arithmetic-class tell (7), option pair
incl. a derived multiplier (7pair), one-sided family on an extreme key (8, from the graders'
`error_directions`), interior tell (9), single bound killing all three on an extreme key (10),
a one-grader template or live duplicate (11). Every decision in `mf28.confirm.json`. **HOLD**
off-blueprint by majority. Drop signals are read from the stage-2 files only.

Difficulty banked = three-grader panel median. **Easy cap per domain at the live mix:
Algebra easy <= max(1, round(0.019 x kept_alg)); Advanced Math easy <= max(1, round(0.031 x
kept_adv))**, earliest in the frozen order first; the rest held in `.held.batch.json`.

## Stage 4 — kept set, gate per domain, insert

`mf28-verdict.mjs --write` writes the per-domain sets; each re-runs stage 0 as a set.
**`mf28-kept.mjs` runs `key-extremity-gate` on EACH domain's kept set separately (>= 40.0%,
refusing). A domain that fails - or has fewer than 10 scorable items, which is no measurement
and not a pass - is held whole**: nothing in it inserted, no item dropped, moved or edited to
pass, no override, no re-run under another rule. Passing domains go to
`sat-math-v28-full.kept.batch.json` and are inserted once:

    BANK_BAND=mixed BANK_COHORT=sat-math-v28-full \
      node scripts/study-bank/math-bank-helper.mjs insert \
      scripts/study-bank/sat-math-v28-full.kept.batch.json scripts/study-bank/mf28.qc.json

after this batch's ledger entry is written onto `ledger.json` re-read from HEAD. Then
`form-capacity.mjs`, `next-form.mjs`, `verify-sat-hard-route.ts math`. REGISTER §5 and the
ledger entry in one commit. Commit locally; no push.

## Stop rule

Stop at the first failed gate, per domain: a batch-level stage-0 bar after the return, a
stage-1 hold or a control above the ceiling, or the stage-4 extremity gate. On a stop nothing
in that domain is inserted and nothing is repaired; the result is recorded with denominators.
