## What changes from v22 (and what does not)

Same target definition, same graders' question, same blind and with-source
halves, same bars, **no auditor and no repair round**. Changes:

1. **Shape: ALL 14 are pure-algebra parameter items.** No context, no word
   problems. Each has at least one constant (k, c, a, b ...) and a stated
   condition, and the OBVIOUS candidate value (the one routine procedure
   produces first) must FAIL a condition the stem states. The explanation names
   that candidate and the condition it fails.
2. **Constructs must be new.** Not any v22 construct (A1 no-solution with a
   coincident-lines candidate; A2 greatest-integer-solution inequality; A6
   system of inequalities with an empty region; A7 solvable-for-every-k
   identity; translation identity; whole-number optimum) and not a live-bank
   construct (proportional-coefficient no-solution / infinitely-many;
   f(x+a) = f(x)+b; f(f(x)); "no solution, greatest integer c" inequality;
   anything quadratic: discriminant, tangency, Vieta). Authors receive the full
   live SAT Algebra dump (415 rows) and the v18/v19/v22 batches.
3. **Construct families, at most 2 items each, split across the halves:**

       half A   FA system + third condition on the solution, where the
                   routine value of the constant makes the system degenerate
                FB a line with a parameter through a fixed point (pivot) meeting
                   a stated segment / intercept condition
                FC a linear function constrained on a whole interval, where the
                   sign of the slope decides which endpoint binds
                FD a one-variable linear inequality whose x-coefficient involves
                   the constant (sign unknown) and whose solution set is given
       half B   FE counting / summing integer values of a constant for which the
                   solution of a two-equation system lies in a stated region
                FF two lines parallel/perpendicular by a constant AND a second
                   condition that rejects the routine root
                FG a two-variable linear inequality (half-plane) required to
                   contain or exclude stated points; boundary inclusion matters
                FH a one-variable linear equation in x with a constant, whose
                   solution must satisfy a stated range or integrality condition

   Half A: FA 2, FB 2, FC 2, FD 1. Half B: FE 2, FF 2, FG 2, FH 1.
4. **Plug-back ban (v22 A2).** No item where trying the options in ASCENDING
   order (and, for a "greatest" stem, descending) reaches the key in 2 or fewer
   substitutions that each take one routine check. Asked quantities that are
   not directly checkable by substitution (a count, a sum of values, a derived
   coordinate) are the intended remedy; a key that is the 3rd/4th option tried
   is the other.
5. **Direction ban (v22 A3).** No item where an increasing/decreasing or sign
   reading available from the stem without solving kills sign-mismatched
   options. If the options straddle zero, the sign of the answer must itself
   require the solve.
6. **Blueprint (v22 B7).** Linear only (SAT Algebra: linear equations in one or
   two variables, linear functions, systems of two linear equations in two
   variables, linear inequalities in one or two variables). At most two
   variables (x, y) plus named constants; no third equation, no three-unknown
   system, no quadratic in x, no absolute value. A constant satisfying k² = n
   (as v22 A1) is allowed; a quadratic solved for x is not.

## Pipeline

author (two halves, separate Claude subagents) -> `verify` (sandbox recomputes
every key and every `distractor_solve`) -> pre-flights -> FREEZE (commit + sha)
-> gate on the frozen file:

- **blind half**: options-only render, three samples of one Claude solver;
- **with-source half**: three fresh Claude graders. Stage 1 on a COLD file
  (stem + options, no key, no explanation): solve, list free eliminations
  INCLUDING the ascending plug-back count and any direction/sign kill,
  exclusivity, difficulty, blueprint. Stage 1 is written to disk BEFORE stage 2
  opens the keyed file (explanations + distractor paths). Stage completion is
  judged by files on disk.

No GPT model anywhere.

- `math-bank-helper.mjs verify`: every key and every `distractor_solve` recomputes.
- `check-sign-pair.mjs`: zero +-pair sets containing the key.
- `check-key-is-composition.mjs`: zero key-as-unique-composite.
- `check-explanation-hygiene.mjs`: zero reviewer-facing text.
- `check-symbolic-hub.mjs` / `check-math-hub.mjs`: run and recorded.
- `key-extremity-gate.mjs`: key at an extreme >= 40% on the authored 14
  (target ~50%; neither extreme above ~70%).
- `stem-duplicates.mjs --family sat` and `check-math-near-dup.mjs`: prompt
  token-Jaccard >= 0.60 against any live SAT Math row, or an option multiset
  equal to a live Algebra row's, is DROPPED before freeze.
- `math-mechanism-dup.mjs 14 <batch>` (reads every live maths row in every
  family, so no BANK_FAMILY switch is needed): every FLAG read by hand; a
  same-mechanism pair with a live row is DROPPED before freeze.
- `merge-halves.mjs`: shared key values / repeated option values across items
  reported; a shared key value is re-authored before freeze.
- All option sets numeric, four choices.

A mechanical pre-flight failure may be fixed by the author before freeze. No
model reader sees any item before freeze.

## Bars (v22's, plus rule 6)

- **Blind:** candidate minus matched control <= +10 points. Unanimity is a
  batch-level RATE against the control's rate, never a per-item drop. Above +10,
  nothing is inserted.
- **Per-item drop**, any one (three graders):
  1. key disputed by any grader (stage-1 cold answer != key after re-check)
  2. not exclusive by majority
  3. distractors weak by majority
  4. median >= 2 of 3 distractors free-strikable without arithmetic (stem
     visible; direction/sign kills count), or the KEY free-strikable by any grader
  5. a `distractor_solve` / explanation path that does not produce its value
  6. **NEW: a majority of graders report that ascending plug-back (descending
     for a "greatest" stem) reaches the key in <= 2 routine substitutions.**
- **EXT-1:** any item a grader explicitly recommends dropping is dropped.
- **HOLD:** any item a grader majority calls off the SAT Algebra blueprint is
  held for Andy (`.held.batch.json`), not inserted.
- **Difficulty:** banked label = three-grader PANEL MEDIAN. Question to graders
  (verbatim from v18/v19/v22): "hard" means the item belongs on the module-2
  hard route because it has a decision point that routine procedure (including
  Desmos) does not bypass; "medium" means careful multi-step procedure reaches
  the key. Easy is rejected, not relabelled.
