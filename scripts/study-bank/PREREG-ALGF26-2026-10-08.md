## Authoring rules (the brief carries each verbatim)

1. **One mechanism per item, all 52 distinct.** Each item declares `mechanism`
   (2-4 short keyword phrases). No item may share its mechanism with another
   in this batch or with any live maths row in any family, or with any held
   Algebra item (v18/v22/v23/v24/v25 held files). A mechanism duplicate is the
   same chain of steps on the same kind of givens to the same asked quantity;
   a new surface story over the same chain IS a duplicate. Authors receive the
   live SAT Algebra dump (426), the all-family live maths dump (3,140), and the
   held/prior Algebra file, and grep them before writing each item.
2. `solve` (independent recompute) and `distractor_solve` for **every**
   distractor, rounding included (skill §2).
3. Distractors from **different named wrong paths**; no derivational hub, no
   key-as-unique-composite, no +-pair containing the key, no closure (key =
   sum/difference/mean/double of two options), no evenly spaced run beside the
   key, no grid of one quantity through factors, no singleton
   parity/sign/integrality/roundness/multiple-of-k tell.
4. **(c) No one-sided error family**: an extreme key needs distractors with at
   least two distinct `error_kind`s **and** errors whose direction is not
   predictable from the stem. Each distractor declares
   `distractor_meta: {error_kind, direction}`.
5. **No cheap single bound on an extreme key**: for each extreme-key item,
   `cheap_bound_check` names the cheapest one-sided bound readable from the
   stem (sign, monotonicity, a stated cap or budget, one-step estimate, the
   shape of the relationship) and shows at least one distractor lies on the
   key's side of it.
6. **(d) Interior parity**: the two interior options (ranks 2 and 3 by value)
   have the same display form and display complexity within 1; the key is not
   the cleaner interior value. **(e)** No two options summing to 1, 90, 180,
   360 (or 100 with %); no shared-denominator structure singling out the key.
7. **Plug-back ban**: no item where trying the options in ascending order (or
   descending on a "greatest" stem) reaches the key in <= 2 routine
   substitutions — in Algebra this means **do not ask for the solution x of a
   one-variable equation or the (x, y) of a system when options can be
   substituted**; ask for a derived quantity (a combination, a parameter, a
   value of an expression, a count, a coordinate of something built from the
   solution). **Direction ban**: no sign/monotonicity reading from the stem
   that kills sign-mismatched options without solving.
8. **Every option is a LEGAL value of the quantity asked** (A86 rule-4 class,
   Algebra form): a count or a greatest/least integer is an integer; a
   quantity the context makes nonnegative is nonnegative; a value fixed under a
   stated cap/budget respects it. An illegal distractor is a free strike.
9. No reviewer-facing text in `explanation`; no option value shared across
   items in one author's file; ASCII hyphen-minus `-` in choices and in
   compound words ("xy-plane"), never U+2212.
10. **Medium means two real steps** (set up then solve, or solve then use the
    result); a single routine step is easy and, under the cap below, will not
    be inserted. Easy items (A05, C08) are real SAT easy items, still under
    rules 1-9. Hard items have a decision point routine procedure (including
    Desmos) does not bypass.

Author fields `mechanism`, `quantity_asked`, `distractor_meta`,
`cheap_bound_check`, `interior_parity_check`, `arith_class_check`, `bounds`,
`self_audit`, `assigned` are stripped before any grader or solver reads the
file.

## Stage 0 — pre-flight (per author file and on the merged 52)

`algf26-preflight.sh <file>` (= `adv24-preflight.sh`, same checks):

- `math-bank-helper.mjs verify`: every key and every `distractor_solve`
  recomputes (N/N, 3N/3N); extremity verdict printed. Mutation: one changed key
  and one changed distractor body must both be refused.
- `check-sign-pair.mjs` zero key-in-pair; `check-key-is-composition.mjs` zero;
  `check-explanation-hygiene.mjs` zero; `check-math-hub.mjs` and
  `check-symbolic-hub.mjs` run and recorded (hub margin > +10 = return).
- **Assigned slot honoured**: every item's key position by value and authored
  difficulty equal the table above (a mismatch is a return).
- `key-extremity-gate.mjs` PASS on the merged set; **key position band on the
  merged set: smallest 12-17, largest 12-17, interior 18-25**
  (`key-rank-position.mjs`); `check-key-magnitude.mjs sat/math` reported.
- `check-interior-niceness.mjs`: any `parity`, `KEY-CLEANER`, `complement` or
  `denominators` line is a return.
- `check-key-arith-class.mjs N` as a reading list; every lone-key line read by
  me against its stem.
- `stem-duplicates.mjs --family sat`, `check-math-near-dup.mjs` (prompt
  Jaccard >= 0.60 or an equal option multiset = return),
  `check-duplicate-option-sets.mjs sat/math`.
- **Duplicates:** `math-mechanism-dup.mjs N` over every live maths row (every
  FLAG read by hand) **plus a hand keyword search of the full live maths dump
  and the held Algebra file per item** (greps run per item; I read every hit
  and decide), recorded per item in `algf26.dupsearch.json`; within-batch
  overlaps checked the same way.
- `merge-halves.mjs`: duplicate ids, shared key values, shared option values,
  closure.

**One return per author** for any stage-0 failure; the returned file re-runs
all of stage 0. An item still failing after its return is **dropped before
freeze**, not returned again. A batch-level stage-0 bar (extremity gate,
key-position band) failing after the return **stops the batch**. No model
reader sees any item before the freeze commit.

## Stage 1 — options-only attack (blind half)

`make-algf26-oo.mjs` (= `make-adv24-oo.mjs` with DOMAIN = Algebra, EXCLUDE =
`v2`, `sat-math-v16-adv` (3 Algebra rows), `sat-math-v17-alg` ..
`sat-math-v26-alg`, `sat-math-v26-algfull`, seed 20261026):
**composition-matched control, one live Algebra item per candidate in the
candidate's AUTHORED band**, numeric option sets only, keys dealt flat per arm,
minus glyph normalised, interleaved. Eligible today: hard 30, medium 139, easy
5 (all >= the authored 8 / 42 / 2). Three blind samples of one Claude solver,
recorded as three samples of one solver. `score-oo.mjs`.

- **Batch HOLD** if candidate minus control > **+10** points.
- **Batch HOLD** if the candidate unanimous-correct rate exceeds the control's
  by > **15** points.
- **Ceiling:** the attainable range of the control is 25% (letter line) to
  100%; both bars can fire only while the control is <= 90%. A control above
  90% = blind half NOT MEASURED: the batch stops (not a pass).
- Per item: unanimity alone never drops; it needs with-source corroboration.
- Reported, not gated: hit rate split extreme-key / interior-key per arm, and
  `check-interior-niceness.mjs --attack` asymmetric / tie split per arm.

An options-only result is never reported as "does not leak".

## Stage 2 — with-source graders (decides per item)

Three fresh Claude graders (D, E, F), each over all frozen items in two runs
(halves of the seeded order). **Stage 1 cold** (`make-grade-render.mjs` of the
stripped frozen file: stem + options, re-dealt, no key/explanation/paths):
solve, exclusivity, free eliminations with stem visible (struck options),
ascending plug-back count, `error_directions` per distractor and `one_sided`,
`extreme_single_bound`, `interior_parity`, arithmetic-class tell, Desmos/insight
bypass, difficulty, on_blueprint, duplicate note. **Written to disk before
stage 2 opens the keyed file** (key, explanation, distractor paths): key_ok,
path_coherent, distractors_weak, drop_recommend, final difficulty. Stage
completion is judged by files on disk.

**Per-item drop, any one:**
1. key disputed by any grader (cold answer != key and not withdrawn as a pure
   arithmetic slip on re-check);
2. not exclusive by majority;
3. distractors weak by majority;
4. median >= 2 of 3 distractors free-strikable without solving, or the key
   free-strikable by any grader (confirmed by me);
5. a `distractor_solve` / explanation path that does not produce its value
   (any grader, confirmed by me);
6. a majority report ascending plug-back reaches the key in <= 2 routine
   substitutions;
7. a confirmed (a)/(b) arithmetic-class or option-structure tell (any grader,
   confirmed by me);
8. a confirmed (c) one-sided error family on an extreme key (any grader,
   confirmed by me, from the graders' `error_directions`, never the author's
   declaration);
9. a confirmed (d)/(e) interior-parity, complement or shared-denominator tell
   (any grader, confirmed by me);
10. an extreme key with a confirmed single bound cheaper than the item's work
    putting all three distractors on or beyond it (any grader, confirmed by me);
11. a mechanism duplicate of a live row or of an earlier item (seeded order)
    in this batch found after freeze (the later item drops);
- **EXT-1:** any grader's `drop_recommend` -> drop.
- **HOLD:** majority off the SAT Algebra blueprint -> held for Andy
  (`.held.batch.json`), not inserted.

**Difficulty banked = three-grader panel median**, question verbatim from
adv24: "hard" means the item belongs on the module-2 hard route because it
has a decision point that routine procedure (including Desmos) does not
bypass; "medium" means careful multi-step procedure reaches the key; "easy"
means one routine step.

**Easy cap = the live Algebra mix.** Live easy is 9/426 = 2.1%. Inserted easy
<= max(1, round(0.021 x kept)), which is **1** for any kept count up to 71 — so
the Algebra easy share stays 2.1-2.3% for any plausible kept. Panel-median easy
survivors past the cap (the lowest id in the frozen file's ORIGINAL id order is
inserted first) are held in `sat-math-v26-algfull.held.batch.json`, not
inserted. Panel-median hard is inserted as hard.

## Stage 4 — kept set, insert

The kept set (inserted items only: medium + hard + capped easy) re-runs stage 0
as a set. **`key-extremity-gate.mjs` on the kept set GATES** (>= 40.0% at k =
4, measured at >= 10 numeric): a failure holds the whole batch — no dropping,
moving or editing items to pass, no override. `check-key-magnitude.mjs
sat/math`, `check-interior-niceness.mjs`, `key-rank-position.mjs` reported on
the kept set. Then, **once, with the band set for a mixed-band insert on the
first run** (adv24 had to insert twice because it was not):

      node scripts/study-bank/math-bank-helper.mjs insert \
      scripts/study-bank/sat-math-v26-algfull.kept.batch.json scripts/study-bank/malgf26.qc.json

the kept file itself (it holds at most one easy item), never by the inserter.

REGISTER §5 entry and this batch's own ledger entry in one commit, the ledger
entry written onto `ledger.json` re-read from HEAD immediately before editing.
Commit locally; no push.
