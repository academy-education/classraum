the probe and the panel are whole-batch reads (each reader sees every item) and SEC25 ran 32 the same way. The

### Cross-item tell check (`ii23-tellsim.mjs`): bars and result on the table
For each type, separately per stem, it searches every single-feature rule (pick f = v or f != v), every two-feature
conjunction, and every odd-one-out rule over the role features (textual wt, wr, wc, same-unit, last-sentence;
quantitative c1, c2, rank). A rule that uses the item's whole **construct** (support: wt & wr & wc, or wt & wr on 4G;
weaken: wt & wc; quantitative: c1 & c2) is the skill, not a tell, and is scored as a guess. Expected accuracy of a
rule on an item = 1/|picked| if it picks the key, 0 if not, 1/4 if it picks nothing.

| Bar | Textual | Quantitative |
|---|---|---|
| B1 best single-feature rule <= 0.50 | **0.475** (support wt=y 0.46; weaken wt=n 0.50) | **0.500** (c1=pass) |
| B2 best pair rule <= 0.65 | **0.637** (support wt=y & wc=tie 0.71; weaken 0.53) | **0.542** |
| B3 one rule picks the key alone in <= 60% of items | **45.0%** (support 6/12, weaken 3/8) | **33.3%** |
| B4 surface rule (letter, rank, last-sentence) <= 0.40 | **0.313** | **0.250** |
| B5 key role <= 40%; no distractor role in > 75% of items | K-ISO 6/20; WKN 10/20 | (key always QK); Q-C1 8/12 |
| B6 author letter sequences distinct | A BDCAADBC, B DABCBCAD, C ADCBBACD, D CCADDBAB | |
| B7 no design x role set repeated; <= 2 role sets repeated across designs | none; A8 = D8 (ratio vs two-condition) | |
| Legality | every option set has exactly one option in the stem's direction once all features apply | |

**What the table changed before this document.** The first draft missed B2 (0.825) and B3 (65%): under weaken, "the
hypothesis group loses and nothing else differs" picked the key 8 of 8 - which turned out to be the construct (wr
does not matter once wt=n), so the construct definition was corrected, not the table. Then a feasibility read found
four rows that could not be built on distinct group pairs (D5's crossed key and crossed distractor are one pair in a
2x2; A2, B1 and D3 asked a three-group design for two T-isolating pairs); the rows were changed and the bars re-met.
Two identical role sets (C3 = D5; B6 = C8) and one within-author repeat (C7 = C8) were removed under B7.

**What it cannot see.** It reads declared roles only: not wording, a uniquely hedged option, a semantic tell, or a
role an author declared wrongly (`meta.profiles` lets the merge check the declaration against the option's group
profile; the text itself is the probe's and the panel's to judge). Passing it means the TABLE does not hand the
solver a rule over roles.

## Rules for every item
II22's author rules (one frame; no option restating the pattern both accounts fit; at least one distractor the
rival predicts; quantitative: all options accurate readings, key needs two or more cells; no single-cell lookup key;
the free-elimination list; no option set where exactly one option crosses the group label; key longest/shortest
<= 2 per author; length ratio <= 1.4; name ranges A-F / G-L / M-R / S-Z, no repeats; real facts correct), with:
- no reversed pair, checked from `meta.compare` against the option text; textual options that merely share every
  word are a NOTE (a crossed pair is legal);
- `meta.roles`, `meta.design`, `meta.stem`, `meta.dir`, `meta.last`, `meta.su`, `meta.ranks` as the slot;
  `meta.profiles` (textual) must reproduce each declared role (`ii23-roles.mjs`); a 4G item declares no confound;
- quantitative: the options do not print the column deciding c2 (or the boundary); `meta.visible_fail` <= 1; no two
  distractors share a derived value to 2 significant figures; trend-break banned; no group-best in this table;
- no proper noun used by any II21/II22 candidate (their `meta.names`); no topic_tag from v17/v21/v22;
- `ii23-tellsim.mjs --work` passes on the declarations.

## Exclusion
`ii23-exclusion.mjs` flags a candidate whose passage word-trigram Jaccard is >= 0.20, whose option set is identical
(case/space/quote/dash-normalised, order ignored), which shares 3+ options verbatim with one item, or whose table
cells are identical, against (a) every live I&I row (paged, count-asserted; 322 at the dry run) and (b) every II21
and II22 candidate (2 frozen batches of 24 plus 8 pre-freeze author files of 6). Authors run it before delivery; it
re-runs on the frozen file at stage 1; a frozen item still flagged is HELD. `rw17-dupscan.mjs` against all live R&W
stays as II22's stage 1.

## Pre-freeze steering probe (NEW)
`ii23-sprobe.mjs`, seed 20262393, reader brief `sat-ii-v23-work/SPROBE-BRIEF.md`.
- **Render.** Two renders (r0, r1), each holding ALL 32 items (passage, table, prompt, options in authored order);
  ids P01..P32 in a seeded order per render; no id, slot, author, key, explanation, topic_tag or meta. A snapshot
  records each item's key letter and the sha256 of its word tokens (passage + prompt + options + table). A second
  render refuses while the snapshot exists.
- **Readers.** Two fresh Claude readers, one per render, never an author, solver or grader of this batch. They answer
  the GRADER-BRIEF phase-1 fields **in the graders' own words** (my_answer, confidence, exclusive,
  second_defensible, n_struck with the graders' strike list, distractor_quality, key_from_one_sentence, difficulty
  with the graders' definition verbatim, off_blueprint, world_knowledge, note), plus `struck`, `not_hard_because`
  (required on easy/medium), and the graders' phase-2 batch question asked cold as `summary.tells` and
  `summary.near_duplicates`.
- **Named MUST-revise:** any reader misses the key; marks it not exclusive or names a second defensible option; gives
  n_struck >= 2, easy, weak distractors, key_from_one_sentence (rule 8), off_blueprint or world_knowledge; NO reader
  rates it hard; any reader rates distractor_quality below strong; a template pair named by both readers names the
  LATER slot. **Listed only:** a pair named by one reader; a tell that names the item.
- **One revision round.** Authors revise every MUST item, keeping the row (letter, roles, design, stem, ranks), then
  re-run the exclusion check and the merge.
- **Verify.** Exit 1 if a MUST item's word tokens are unchanged (whitespace or punctuation edits do not count; a
  table-cell change does), a key letter moved, or an item vanished or appeared. `ii23-merge.mjs --freeze` refuses
  unless verify exits 0.
- **Limits.** Two readers against the gate's median of three, both samples of one model; verify proves an edit, not
  an improvement. The probe decides nothing at the gate. Its pre-revision ratings are kept and reported against the
  panel's results in WIC27's table form, so whether it predicted the panel is measured, not assumed.

## Pipeline (II22's stages 0-5, the probe inserted before the freeze)
1. Four authors (at most 3 at once: A+B+C, then D). Each runs `ii23-exclusion.mjs` and `ii23-merge.mjs` before
   delivery. A row an author reports as unbuildable is changed only by an amendment written before the probe, with
   `ii23-tellsim.mjs --table` re-run.
2. `ii23-merge.mjs` on all four: 0 problems (this includes the tell check on the declarations).
3. **Probe:** `ii23-sprobe.mjs render`; readers r0 + r1; `score`; ONE revision round (at most 3 authors at once);
   `verify`.
4. **Stage 0, freeze:** `ii23-merge.mjs --freeze` (refuses unless 0 problems, 32 items and verify green; strips
   meta); sha recorded and committed with the ii23 scripts. Nothing is repaired after the freeze.
5. **Stage 1, shape:** `bank-helper check`; `rw17-dupscan.mjs` against all live R&W; `ii23-exclusion.mjs` on the
   frozen file. Dup-scan or exclusion flags are HELD.
6. **Stage 2, options-only:** `rw17-oo-render.mjs ii <frozen> --tag ii23-oo` (the RW17 control: 12 hard textual
   CoE + 12 quantitative CoE live), three fresh Claude solver samples (`OO-SOLVER-BRIEF.md`), `score-oo.mjs`.
7. **Stage 3, elimination:** `elimination-paired.mjs --domain "Information and Ideas" --match subskill --ratio 1`,
   on all 32 frozen items.
8. **Stage 4, with-source:** graders d, e, f (`GRADER-BRIEF.md`, unchanged from II22 but for ids); phase 1 cold,
   sha256 into `ii23.ws-phase1.sha256` before the key file is written; phase 2 with the key; `ii23-gate.mjs`.
9. **Stage 5, tells:** `verify-answer-key-spread.ts --batch <kept>` (and on the frozen 32, since it refuses small
   n); key strictly longest and strictly shortest <= 35% of kept; no proper noun repeated within the kept set.
10. mk-rw-qc / ledger; insert as `rw-v23-ii-hard`; `verify-sat-hard-route.ts reading_writing 13` and
    `form-capacity.mjs`.

**The run stops at the first failed gate** (options-only bar, elimination bar, the gate's cold-miss stage bar).

## Bars (II22's, unchanged)
- **Options-only (batch):** candidate minus control <= **+10**; above that the batch is HELD whole. The control must
  land in **(30%, 90%]**, else the half is NOT MEASURED and the with-source half decides. **Ceiling, stated before
  the run:** the reject threshold is control + 10, so it is reachable only while the control is below 90%; at the
  II21 and II22 controls (87.5%, 72.2%) it sat at 97.5% and 82.2%, both attainable. A control in (87.5, 90] leaves
  under 2.5 points of headroom, and the report says so rather than calling the pass a measurement.
- **Elimination:** margin <= **+20**, control <= 80%.
- **With-source, per item** (`ii23-gate.mjs`, verdict rules byte-identical to ii22-gate.mjs): gate-verdict rules
  1-6; key above ceiling per any grader; a distractor above ceiling per >= 2; an antonym pair per >= 2;
  recommend_drop by any; panel-median easy DROPPED; majority off_blueprint or a dup-scan/exclusion flag HELD;
  **rule 8:** majority key_from_one_sentence caps the banked difficulty at medium. A cold miss counts as key_ok
  false.
- **Stage bar:** any grader cold-misses more than 10% of items -> FAIL. On 32 items that is **more than 3**
  (`floor(32 x 0.10)`), where II22's 24 allowed 2.
- **Difficulty** is always the panel MEDIAN, never the author's label or the probe's. Medium survivors are inserted
  and do not move the hard route.
- The three solvers are one model sampled three times: margins stand, intervals are about sqrt(3) wider than
  printed. An options-only pass is reported as "the option set alone does not decide it", never "the batch does not
  leak".

**Expected direction, stated so it cannot be read after.** Options-only, the textual options share one frame by
rule, so the option set alone should carry little signal; the quantitative keys' headline ranks are flat (3/3/3/3).
The tell check's surface bound (B4: 0.31 textual, 0.25 quantitative) is the table's ceiling for a shape rule, not a
prediction of the solvers, who read words.

## What the method still cannot fix
- The brief and declarations are wording discipline; an author declares the roles it believes it built. The probe
  and the panel decide, and `meta.profiles` only checks the declaration is self-consistent.
- The tell check sees roles, not words. A semantic tell (a uniquely hedged key, a key that is the "interesting"
  claim) is invisible to it.
- Two probe readers are two samples of one model, as the three solvers are.
- The quantitative hard rate has been 12.5%; the brief targets the signature the three hard tables shared, which is
  a description, not a demonstrated cause.
- The gate is model-only; the human sitting decides verbal cohorts.
